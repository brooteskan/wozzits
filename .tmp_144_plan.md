## Implementation plan

### Phase 1 — Scene JSON descriptor binding parse / export / fingerprint

Add `descriptor_bindings` to `SceneRenderShaderAsset` as an authored JSON array, wire it through parse, export, and fingerprint.

**Authored shape:**
```json
"descriptor_bindings": [
  {
    "kind": "structured_buffer_srv",
    "visibility": "pixel",
    "semantic": "mesh_field_visualization",
    "shader_register": 0,
    "register_space": 0,
    "descriptor_count": 1
  }
]
```

**Files:**

- **`window_engine/engine/assets/scene/scene_asset_data.h`**
  - Add `SceneDescriptorBindingAsset` struct (all string fields: `kind`, `visibility`, `semantic`, plus `uint32_t shader_register`, `register_space`, `descriptor_count`)
  - Add `std::vector<SceneDescriptorBindingAsset> descriptor_bindings;` to `SceneRenderShaderAsset`

- **`src/engine/assets/scene/scene_compilers.cpp`**
  - After the existing `render_shader` string field parsing (around line 2297): parse `"descriptor_bindings"` JSON array, read each object's fields, push into `component.descriptor_bindings`

- **`src/engine/assets/scene/scene_json_export.cpp`**
  - In `render_shader_value()` (around line 930): if `shader.descriptor_bindings` is non-empty, emit `"descriptor_bindings"` as a JSON array

- **`src/engine/assets/scene/scene_fingerprint.cpp`**
  - After the existing render_shader string mixing (around line 563): mix `descriptor_bindings.size()`, then for each binding mix all 6 fields

**Test:** Extend `scene_render_shader_roundtrip_tests.cpp` with a test that includes `descriptor_bindings` in the JSON, verifies parse produces correct fields, export contains the array, re-parse produces identical fingerprint.

**Verification:** Existing tests still pass. New roundtrip test confirms no loss.

### Phase 2 — Convert authored descriptor strings to DescriptorBinding values

Map authored string tokens (`structured_buffer_srv`, `pixel`, `mesh_field_visualization`) to the existing `DescriptorKind`, `ShaderVisibility`, and `DescriptorSemantic` enums during materialization, and populate `CustomRenderProgramDesc.descriptor_bindings`.

**Files:**

- **`src/engine/assets/scene/scene_authoring_materialize.cpp`**
  - Add string-to-enum helpers: `parse_descriptor_kind()`, `parse_descriptor_visibility()`, `parse_descriptor_semantic()`. Reject unknown tokens (first-milestone scope: only `structured_buffer_srv` / `pixel` or `vertex` or `all` / `mesh_field_visualization`)
  - In `materialize_render_shader()`: iterate `shader.descriptor_bindings`, convert each `SceneDescriptorBindingAsset` into a `DescriptorBinding`, append to `desc.descriptor_bindings` on the `CustomRenderProgramDesc`
  - Update `render_shader_cache_key()` to include descriptor binding fields so the renderable cache key changes when bindings change

**Test:** Add a materialize test that includes a `mesh_field_visualization` descriptor binding in the scene JSON, materializes, and verifies `RenderProgramData.descriptor_bindings` contains exactly one entry with the expected `DescriptorKind::StructuredBufferSRV`, `ShaderVisibility::Pixel`, `DescriptorSemantic::MeshFieldVisualization`, and correct register/space/count.

**Verification:** Existing materialize tests still pass. Custom programs without descriptor bindings produce empty `descriptor_bindings` as before.

Both were built during #143 for future use.

**Verification needed:** Confirm that when `descriptor_bindings` is non-empty on a custom `RenderProgramData`, the root signature serializes correctly and the PSO creates without error. If not, fix issues in the factory.

### Phase 4 — Submit path: bind field visualization resource for custom programs

Currently the mesh submit path (in `dx12_submit.cpp`) has two separate mechanisms:
- **Builtin path:** `bind_mesh_field_heatmap_resource()` hardcodes root parameter 1 for `MeshFieldHeatmap`
- **Custom path:** only binds root constants (index 0); no descriptor tables

Bridge the gap: when a custom render program is in use and its binding layout has a `MeshFieldVisualization` semantic, bind the same GPU resource the builtin path uses.

**Files:**

- **`src/engine/render_backends/dx12/dx12_submit.cpp`**
  - In `submit_mesh_commands()` (around line 972-986): after setting root constants, if `render_program_cache` is available and the resolved entry has a valid `render_program`:
    1. Look up `get_binding_layout(resolved->render_program)`
    2. Find the `RealizedDescriptorBinding` with `semantic == MeshFieldVisualization`
    3. Get `mesh_field_visualization_resource` from `resolved`
    4. Look up the DX12 field visualization resource via `get_mesh_field_visualization()`
    5. Call `SetDescriptorHeaps()` + `SetGraphicsRootDescriptorTable()` at the realized binding's `root_parameter_index` with `field->srv_table.gpu_at(0)`
  - Factor the existing `bind_mesh_field_heatmap_resource()` so the new custom path shares the DX12 resource lookup logic

**Test:** The end-to-end test from Phase 5 covers this. Unit-level verification: the submit path does not crash and the draw call emits.

### Phase 5 — Validation + end-to-end test

Add validation that rejects `mesh_field_visualization` semantic when the renderable has no field visualization asset, and add the full end-to-end GPU test.

**Files:**

- **`src/engine/assets/scene/scene_authoring_materialize.cpp`**
  - In `materialize_render_shader()`: if any authored descriptor binding has semantic `mesh_field_visualization`, verify that the node also has `mesh_render_style.field_visualization_enabled == true` and that a field visualization asset will be materialized. Error if not.

- **`tests/asset_scene/scene_materialize_render_shader_tests.cpp`** (extend)
  - **`MeshRenderShaderWithFieldVisualizationDescriptorBinding`**: full pipeline test. Scene JSON with mesh node having `mesh_wavelet_analysis` + `mesh_render_style` (field viz enabled) + `render_shader` with a `descriptor_bindings` array containing the MeshFieldVisualization SRV. Uses real HLSL with `StructuredBuffer<float> MeshFieldValues : register(t0)` in the pixel shader. Verify:
    - Materialization succeeds
    - `RenderProgramData.descriptor_bindings` has 1 entry with correct semantic/kind/visibility
    - Renderable has valid `render_program` handle AND valid `mesh_field_visualization_asset`
    - Pipeline realizes successfully
    - Binding layout has `MeshFieldVisualization` descriptor at expected root parameter index

  - **`MeshRenderShaderFieldVisualizationRejectsWithoutFieldEnabled`**: verify materialization returns an error when a descriptor binding requests `mesh_field_visualization` but the node has no field visualization enabled.

**Verification:** All existing tests pass (render program, roundtrip, materialize, compute kernel). New tests cover the descriptor bridge end-to-end.
