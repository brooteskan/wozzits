## Defects found in the uncommitted changes

1. **Leftover debug logging.** Raw `fprintf(stderr, ...)` diagnostics (cache HIT/MISS, "SUCCESS", "FIELD CREATION FAILED", node dumps) in `scene_authoring_materialize.cpp`, `scene_instance.cpp`, and a block explicitly marked "diagnostic logging" in `behavior_gpu_compute_executor.cpp`.
2. **GPU use-after-free hazard in `GpuResidentFieldTable::replace()`.** It calls `release_mesh_field_visualization()` on the prior resource immediately (`values_buffer->Release()` is immediate in `dx12_mesh_field_visualization.cpp`), while the render queue may still have in-flight command lists from the previous frame binding that SRV.
3. **Per-frame publish cost.** Every published output every frame: new committed resource + one-shot command list + `execute_and_wait` (full GPU stall) **plus** an unconditional full CPU `readback_buffer` of the output port (~17 MB/frame for the 4.25M-vertex demo mesh).
4. **Validation failures are silent.** Issue requires "fails with a clear diagnostic"; current behavior is stderr-only, no report/event signal, dispatch still counted successful.
5. **Over-broad auto-enable.** Materialization force-enables `field_visualization_enabled` for *every* mesh node with a `compute_kernel`, even kernels that never publish a mesh field. Changes renderable cache keys and writes back render styles for unrelated kernels.
6. **Dead branch** in `MeshDerivedFieldAssetModule::create_behavior_field_placeholder` — both `register_asset` outcomes return the same value. (The matching `render_program_asset_module.cpp` change — returning the key when the asset is already registered — is a legitimate idempotency fix but deserves a comment and ideally its own commit.)
7. **`find_mesh_field_publish_target` early-returns `{}`** from inside the target loop on the first mismatch instead of `continue`, so a node with multiple viz targets can't fall through to a later matching one.
8. **Non-portable sample content.** `scene_editor_handles_export.scene.json` references `C:\Users\david\OneDrive\Documents\Gaea\Builds\Mountain 3\003\Mesher.glb` plus machine-specific camera pose; `"vertex_count": 4253332` hard-codes that specific mesh.
9. **Untracked-but-required files.** `shaders/compute/` (incl. `landscape_field_cs.hlsl`, referenced by the scene JSON) and `shaders/mesh_wavelet/` are untracked; committing the scene without them breaks the sample. `.tmp_144_plan.md` / `.tmp_behavior_compute_render_bridge_issue.md` are scratch and should not be committed.
10. **Silent draw drop** in `bind_custom_render_program_descriptor_resources` — the `default:` case returns false (skips the draw) with no diagnostic for any future non-MeshFieldVisualization semantic.

## Phased correction plan

### Phase 1 — Hygiene (make the tree landable)
- Remove all debug `fprintf` blocks (executor, materialize, scene_instance) or convert load-bearing ones to `wz::Logger` at debug level; drop the now-unneeded `<cstdio>` includes.
- Simplify the dead branch in `create_behavior_field_placeholder`; add a comment on the intentional "already registered is success" semantics here and in `render_program_asset_module.cpp`.
- Fix `find_mesh_field_publish_target` to `continue` instead of `return {}` on per-target mismatch.
- `git add` the `shaders/compute/` and `shaders/mesh_wavelet/` directories; keep `.tmp_*.md` out of the commit.

**Verify:** build + existing test suites (roundtrip, materialize render shader, compute kernel) pass.

### Phase 2 — Publish lifetime & diagnostics correctness
- **Deferred release in `replace()`:** don't `Release()` the previous resource while it may be referenced by in-flight render command lists. Either (a) add a fence/frame-delayed pending-release list on the DX12 device (drained after the render queue fence passes), or (b) update the existing destination resource in place (see Phase 3, which subsumes this).
- **Clear diagnostics:** route publish-target/stride/element-count mismatches through the logger (rate-limited), and surface failure in `BehaviorGpuDispatchReport` (e.g. `publish_failed` counter + reason list) so callers/tests can assert on it. Per the issue, an invalid shape should *fail* visibly, not silently skip.
- Add the missing negative tests: mismatched element count, wrong stride, missing/invalid field target → expect `published_mesh_fields == 0` and the failure surfaced in the report.
- Add the duplicate-update test: dispatch twice against the same target, expect `replace()` succeeds both times, `find()` stays valid, no failure.

**Verify:** new tests pass; run with DX12 debug layer to confirm no resource-deletion-while-in-flight validation errors.

### Phase 3 — Per-frame performance
- Make the destination resource persistent per `(field_key, channel_id)`: add an "update from GPU source" path in `dx12_mesh_field_visualization.cpp` that copies into the existing buffer/SRV instead of `CreateCommittedResource` + new SRV + `execute_and_wait` every frame. First milestone may keep one wait, but must not reallocate or churn descriptors per frame. This also eliminates the Phase 2 release hazard for the steady-state path.
- Skip the CPU `readback_buffer` for ports that were published as mesh fields (or gate readback behind an explicit per-port flag in the ABI) — a 4M-vertex field should not be copied to the CPU every frame just to be discarded.

**Verify:** demo scene frame time before/after; behavior publish test still passes.

### Phase 4 — Scope the auto-enable (explicit opt-in)
- Replace the blanket "node has `compute_kernel` ⇒ enable field visualization" heuristic with explicit intent: enable the placeholder-field path only when the node's `render_shader.descriptor_bindings[]` contains a `mesh_field_visualization` semantic (or `mesh_render_style.field_visualization_enabled` is authored). The `debug/multiply_u32`-style kernels must not grow render styles, placeholder assets, or new cache keys.
- Keep the materialize-time validation that a `mesh_field_visualization` descriptor requires a field source (already implemented and tested).

**Verify:** materialize tests; a compute-kernel-only node without descriptor bindings materializes identically to before this branch.

### Phase 5 — Engine-owned mesh vertex data input (remaining issue requirement)
- Add an input-port resource ref (e.g. `WZ_GPU_RESOURCE_REF_MESH_VERTEX_DATA`) so a kernel can bind engine-owned vertex data (positions, or position+normal+uv) without the plugin uploading `initial_data` each dispatch. Executor resolves it from the entity's mesh via the asset library, same lookup path as the publish target.
- Let the executor fill `element_count` for publish ports from the resolved target so the plugin no longer needs a `vertex_count` config; drop the `"vertex_count": 4253332` hack from the sample scene/plugin.
- Test: kernel with an engine-bound vertex input + published output runs without any `initial_data`.

### Phase 6 — Sample project portability + commit split
- Replace the absolute Gaea GLB path with a repo-relative asset or a procedural high-density grid fallback; revert incidental editor camera/scale churn unless intentional.
- Land as separate commits: (1) descriptor-binding completion (#144 leftovers: parse/export/fingerprint/materialize/dx12_submit + their tests), (2) the behavior→render bridge (#145 core: ABI, executor publish, placeholder asset, replace(), game_app), (3) mesh_trials sample content.

## What stays as-is
- Placeholder-field design (stable key + element count from mesh at compile time) — sound.
- Copy-don't-wrap publish (engine owns lifetime) — matches the issue's lifetime requirement.
- `D3D12_RESOURCE_STATE_NON_PIXEL_SHADER_RESOURCE | PIXEL_SHADER_RESOURCE` destination state — required now that the demo VS reads the field.
- ABI bump to 19 and the `wz_gpu_set_structured_output_mesh_field` helper.
