## Goal

Allow behavior-driven HLSL compute kernels to produce per-mesh data that can be consumed by scene-authored render shaders through the existing `mesh_field_visualization` descriptor binding.

Today there are two adjacent paths:

- `mesh_wavelet_analysis` runs through asset/materialization. It creates a `MeshDerivedFieldAsset`, registers GPU-resident field buffers in `GpuResidentFieldTable`, and the renderer can bind the selected channel as `mesh_field_visualization`.
- Behavior `compute_kernel` dispatch can run HLSL from behavior/events, but output buffers are transient. The executor reads outputs back into completed events and releases the GPU buffers. Nothing publishes those outputs as renderable mesh fields.

## Desired path

1. A behavior submits a compute job for a mesh entity.
2. The compute kernel writes one `float` per mesh vertex, or writes a compatible channel layout.
3. The executor wraps or copies the output GPU buffer with `create_mesh_field_visualization_from_gpu_source(...)`.
4. The result is registered in `assets.gpu_resident_fields()` under a `MeshDerivedFieldAsset` key and channel id.
5. A renderable with `mesh_render_style.field_visualization_enabled` and a `render_shader.descriptor_bindings[]` entry for `mesh_field_visualization` binds that output.
6. The custom HLSL render shader can read:

```hlsl
StructuredBuffer<float> MeshFieldValues : register(t0);
```

## Implementation notes

- Add behavior job/API metadata for render-published outputs, likely including:
  - target mesh/entity
  - target field asset key or stable authored field id
  - channel id
  - element count / stride validation
- Add a way for behavior compute to bind engine-owned mesh vertex data instead of requiring the plugin to upload `initial_data` each dispatch.
- Add update/replace semantics to `GpuResidentFieldTable`; current `add()` rejects duplicate field/channel pairs, but behavior output may update frame-to-frame.
- Ensure GPU resource lifetime is owned by an engine table/cache, not by the transient behavior dispatch buffer list.
- Validate that output element count matches the mesh vertex count and stride is `sizeof(float)` for the first milestone.
- First milestone can support only vertex-domain `Float1` mesh fields and the existing `mesh_field_visualization` render semantic.

## Tests

- Behavior compute output can be registered as a resident mesh field and found through `assets.gpu_resident_fields().find(field_key, channel_id)`.
- Duplicate frame updates replace the prior resident field instead of leaking or failing.
- A renderable using a custom `render_shader` with `mesh_field_visualization` descriptor resolves the behavior-produced GPU field.
- Invalid output shape, missing mesh, or mismatched vertex count fails with a clear diagnostic.
